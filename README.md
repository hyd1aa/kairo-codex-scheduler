# Kairo

轻量 Rust 工具，在预设时间自动预热 Codex 五小时额度窗口。[English](README.en.md)

一键安装 → 检测官方 Codex 登录 → 自动待命 → 到预设时间检查额度并按条件预热。

## 一键安装

```sh
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/hyd1aa/kairo-codex-scheduler/main/install.sh | sudo bash'
```

自动下载 GitHub 最新正式版，验证 SHA256，部署原生程序与 systemd 开机自启服务。**安装即授权 Kairo 在额度和安全条件允许时自动执行预热；菜单03可以随时暂停。** 官方 OAuth 和 MFA 由用户本人完成。

新安装直接使用安装用户（sudo 时为 SUDO_USER）的官方 Codex 登录目录，不复制或修改官方凭证。先登录再安装会自动验证并待命；先安装再登录时，服务会检测登录文件，无需重启、绑定或启用。在安装用户下执行 `codex login`，或进入菜单04完成登录。旧安装保留服务用户和已有 OAuth，不会强制重新登录。

## 自动运行

本机缺少历史记录不会触发固定五小时等待。Kairo 验证 OAuth 所属用户、服务端账号、五小时及每周额度，并建立本机基线。有效窗口会正常待命；额度不可验证、账号变化或明确实例冲突时停止请求并报告原因。

默认按系统本地时区在 06:00、11:00、16:00、21:00 检查。可新增、修改、删除时间。若16:00窗口仍有效，显示跳过及后续预设机会，不会在 reset_at 后偷偷补发，也不会把跳过说成激活成功。每次实际请求前重新检查额度并持久化防重记录；失败保留请求证据并安全退避。关机期间错过的时点不会集中补发。

服务端可能以新的完整五小时零使用窗口表示当前空闲；只有额度数据符合校验和本机防重条件时才允许预热。不人为重置、加速或突破官方额度。服务端额度无法完整证明其他机器的请求历史，也无法识别所有并发调度器；不保证跨机器绝对防重复。

## 简洁菜单

```sh
sudo kairo
```

| 编号 | 菜单 |
| --- | --- |
| 01 | 查看状态与额度 |
| 02 | 设置预热时间 |
| 03 | 启动 / 暂停 |
| 04 | Codex 登录与账号 |
| 05 | 更新 / 更多设置 |
| 06 | 退出 |
| 00 | 退出 Kairo |

首页只显示开启状态、登录状态、上次请求结果、下次机会及真实额度缓存。时间使用“今天 / 明天”和本地时分。额度显示查询时间，旧缓存明确标记，不伪装成实时数据。中英文、SSH、tmux、小屏终端均使用数字加 Enter 操作，00 返回。日志、服务、语言、诊断与卸载位于菜单05。

只有真实请求成功且后续倒计时证据符合条件，才显示成功。请求成功但证据不足时显示待确认。详细诊断保留窗口证据及归因限制。

## 升级与兼容

```sh
kairo status
kairo --json status
sudo kairo update online
```

升级保留预热时间、OAuth 路径、请求和确认记录、账号保护及主动暂停。缺失部分状态时用剩余有效记录与服务端额度重建；损坏文件或账号不匹配会阻止运行，不覆盖证据。旧恢复记录保留为迁移证据，固定恢复计时退出正常执行路径。`onboard` 与 `enable` 保留为启动兼容入口，不需要生产审批或独占确认。

若 v0.2.5 的旧内置更新器因缺失记录而在加载新版前拒绝升级，重复运行上方一键安装命令即可由新版升级器接管；无需恢复命令或重新 OAuth。新版仅对确实缺失的主记录读取有效备份，损坏的原件不会被静默覆盖。

卸载默认保留状态：

```sh
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/hyd1aa/kairo-codex-scheduler/main/uninstall.sh | sudo bash'
```
